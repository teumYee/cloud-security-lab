# Network Basics

## 1. IP Address

### Q1. IP 주소는 무엇인가?

- 3계층에서 쓰이는 프로토콜. (프로토콜이 아님)
- 단말 장치 사이에서 출발지에서 목적지 사이 최적의 경로를 찾아주는 데 쓰이는 논리적인 주소
- 정확히는 네트워크 상에서 특정 단말을 식별하는 고유 번호.
- 컴퓨터 하나하나마다 부여되는 걸로 알고 있는데 그래서 지금 고갈 위기이다. 이런 부족한 IPV4를 대체할 IPV6이 나왔지만, 아직도 우리는 IPV4를 쓰고 있음.

### Q2. Public IP와 Private IP의 차이는 무엇인가?

- 이름 그대로 접근할 수 있는 / 없는 공공 ip와 사설 ip이다.
- 보완하자면, Private IP는 인터넷 라우터에서 전달되지 않도록 규정되어 있어 외부에서 직접 접근 불가. NAT/포트포워딩을 통해서만 외부 접근 가능.

### Q3. 127.0.0.1은 무엇인가?

- c클래스와는 무관
- 자기 자신. localhost
- IPV4에서 루프백 주소로 예약된 특별한 주소
- 만약 127.0.0.1:8000이라면 내 컴퓨터 안에서 8000번 포트로 실행 중인 서버로 접속한다는 뜻.
- 127.0.0.1 자체는 항상 존재하지만, :8000 포트에서 서버 프로세스가 열려 있어야만 연결이 가능함.

## 2. Port

### Q4. IP와 Port의 차이는 무엇인가?

- IP는 3계층에서 쓰이는 단말과 단말 사이 최적의 경로를 찾아줄 때 사용되는 단말의 고유한 논리적인 주소. (찾아갈 때 필요함.) Port는 그런 단말에 도달했을 때 단말 내에서 어떤 프로토콜을 찾아가면 되는지에 대한 주소 같은 것. http를 쓰고 싶으면 80번이고, ssh는 22번 이런식으로...
- 보완 : Port는 프로토콜이 아님. 프로세스/서비스를 구분하는 번호.

### Q5. 하나의 서버에서 웹 서버와 DB 서버가 동시에 실행될 수 있는 이유는?

- 같은 ip라도 서로 다른 port 번호를 사용하기 때문. 따라서 하나의 서버에서 여러 서비스가 동시에 실행됨.

## 3. TCP / UDP

### Q6. TCP와 UDP의 차이는 무엇인가?

- 전송 계층에서 쓰이는 프로토콜
- TCP는 신뢰성을 보장하고, UDP는 비신뢰성으로 TCP에서 쓰이는 흐름 제어와 오류 제어 기능을 제공해주지 않는다. 대신에 빠름. 그래서 빠른 속도를 원하는 UDP에 QUIC을 추가한 버전도 등장했다고 보안 시간에 배웠었다.

### Q7. HTTP 통신에서는 TCP가 어떤 역할을 하는가?

- HTTP 메시지가 안전하게 서버까지 전달되도록 하는 기반 역할을 함. (3-way handshake), 데이터 전송의 신뢰성 보장, 순서 유지, 오류 검출 및 재전송 담당.

## 4. Communication

### Q8. 브라우저에 https://example.com을 입력하면 어떤 일이 발생하는가?

- 예시 답안 :

1. DNS 조회 : 도메인을 IP 주소로 변환. (길찾기 앱 실행) -> 브라우저가 DNS에게 길을 물어보고, DNS 서버가 IP 주소를 알려줌. (여기야)
2. TCP 연결 : 해당 IP와 Port(443)으로 연결 (정중하게 찾아가서 초인종 누르기)
3. TLS 핸드셰이크 : HTTPS이므로 암호화 채널 설정 (우리만의 비밀 암호 설정 후 안전한 통로가 만들어짐)
4. HTTP 요청 전송 : 브라우저가 서버에 요청 (이제 이 통로를 통해 요청을 할 수 있음)
5. 서버 응답 : HTML, CSS, JS 등 리소스 반환
6. 렌더링: 브라우저가 화면에 표시 (요청한 결과가 나옴)

- 추가적으로 DNS가 IP를 알려주면 브라우저는 TCP 연결을 시도하고, 그 연결 대상이 Nginx일 수 있음. Nginx는 TCP 연결을 받아서 클라이언트와 직접 통신하며, 내부 서버로 요처을 전달하거나 응답을 대신 처리함.

- example.com 이라는 문자열만 알고 있는 컴퓨터가 어떻게 실제 서버를 찾아갈 수 있는가?

1. 브라우저가 먼저 DNS 서버에 질의함.
2. DNS는 example.com -> IP 주소를 알려줌.
3. 그 IP 주소를 이용해 TCP 연결을 맺고, 그 이후에 HTTP 요청을 보냄. 문자열 도메인을 숫자 IP로 변환하는 과정이 DNS의 역할

### Q9. AWS EC2에서 Nginx 실행

- 사용자가 접속했을 때
  - IP
    - EC2에서 인스턴스를 식별하는 주소
    - 사용자의 브라우저가 이 IP를 목적지로 삼아 패킷을 보냄.
  - Port
    - EC2 안에서 열어둔 창구. 로컬로 치면 8000? 다만 퍼블릭이라 인터넷에서 어디든 접근 가능
  - Process (Nginx)
    - 80번 포트에서 대기 중인 프로그램
    - 브라우저의 요청을 받아 정적 파일을 제공하거나, 내부 애플리케이션 서버로 전달.
  - HTTP
    - 브라우저와 Nginx가 실제로 주고받는 대화 규칙
    - "GET /index.html" 같은 요청을 보내고, Nginx가 HTML 응답을 돌려줌.
